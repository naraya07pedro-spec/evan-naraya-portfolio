# Source and visual system

This is a static website. There is no application backend, framework or production npm runtime dependency.

- `index.html`: existing semantic content, source links, identity metadata and downloadable resume references.
- `assets/css/portfolio.css`: the production stylesheet, retained verbatim before appended accessibility-only states.
- `assets/js/portfolio.js`: production scroll interpolation, coalesced into one animation frame per scroll/resize event; original thresholds and interpolation values remain intact.
- `assets/images/`: the original 1122 × 1402 WebP, with unchanged SHA-256.
- `assets/resumes/`: unchanged previously published lightweight PDFs while publication of the approved original v3 files is blocked; never generated by the website.
- `docs/`: claim provenance, audit, deployment and limitations.
- `scripts/`, `tests/`: development-only tooling; no code from these directories is loaded by the page.

The introduction, statement, violet planet expansion and two sticky project scenes remain in the original order. JavaScript maps section progress to CSS custom properties. Ordinary sections use IntersectionObserver for the original reveal treatment. The pointer follower preserves its original easing and sleeps after convergence. Motion preference changes are handled live.

Keyboard-only focus moves a faded scene into its readable scroll state. Scrollable architecture panels have a region name and tabindex. Reduced-motion links retain pointer interaction. The no-JavaScript fallback reveals supporting sections.

## Preservation gate

`docs/baseline.json` pins the actual production source. Visual tests retrieve that immutable HTML from Git, render it alongside the current source in the same engine, and compare hero, statement, planet entry/expansion, both projects and contact at all seven required widths. Full-page images are also recorded; sticky scenes require the viewport states for meaningful review.

A maximum 0.05% changed-pixel tolerance accommodates rasterization jitter. It is not permission for a layout change. Initial results and final hosted preview verification are recorded in the audit. Owner approval is required before updating the baseline commit.

## Boundaries

The original mobile navigation disappears at 760 px. Contrast, small touch targets and any overlap needing visual changes are documented, not silently redesigned. Automated accessibility gates prohibit new violations; they do not certify WCAG compliance. The current production Netlify badge is injected by hosting and is not in Git source. Screenshots distinguish browser production, controlled source regression and deployed preview.

## Current release blocker

Automatic approval review rejected GitHub publication of the authentic original resumes because they include a phone number and personal contact information whose public egress it considered unauthorized. This public branch contains only the already-public reconstructed PDFs from the production baseline. These are not represented as the authentic approved originals. The original v3 files were inspected and their proposed downloads passed locally; publication is pending explicit owner approval. No private PDF bytes or new contact data are in this branch history.

Run `npm run verify:release` before any production decision. It currently fails because the public PDFs do not match the approved originals in `docs/resumes.json`. General website CI passing does not resolve this blocker.
